# Приложение для iPhone

Третий вариант рядом с Android-приложением и веб-версией. Это обычное приложение для
iPhone на SwiftUI, с виджетами для экрана блокировки.

## Устройство

| Папка | Что там |
|---|---|
| `ios/ReciCore/Sources/ReciCore/` | логика без iOS: правила обучения, хранение, файл прогресса, транслитерация |
| `ios/ReciCore/Tests/ReciCoreTests/` | тесты логики: общие сценарии из `tests/`, файл прогресса, тексты |
| `ios/App/` | приложение на SwiftUI: карточка, поиск, справочник, настройки |
| `ios/Widget/` | виджеты: карточка, «Знаю» и «Не знаю» |
| `ios/Shared/` | общее для приложения и виджетов: хранилище в App Group, ответы с экрана блокировки |
| `ios/UITests/` | тесты интерфейса в симуляторе |
| `ios/project.yml` | описание проекта Xcode для XcodeGen |

- Правила обучения в `Repo.swift` повторяют `Repo.kt` и `web/js/repo.js`. Меняйте их
  вместе: общие сценарии из `tests/learning-scenarios.json` покажут, если реализации
  разойдутся.
- Словарь, справочник и шрифты берутся из Android-части, как и в веб-версии.
- Файл прогресса тот же, что у Android и веба: прогресс переносится между всеми тремя.

## Экран блокировки

iOS не даёт приложению рисовать на экране блокировки и самому менять обои. Поэтому в
настройках есть переключатель с двумя вариантами.

1. **Виджеты.** Широкий виджет «Карточка» показывает слово и перевод. Круглые виджеты
   «Знаю» и «Не знаю» отвечают на карточку прямо с экрана блокировки и сразу показывают
   следующую. Приложение просит iOS выполнять ответ без разблокировки; потребует ли iOS
   всё же Face ID, надо проверить на телефоне. Нужен iOS 17 или новее.
2. **Обои.** Действие «Обои с карточкой» для приложения «Команды» рисует текущую карточку
   картинкой. Автоматизация в «Командах» ставит её на экран блокировки: например, каждый
   час. Отвечают те же круглые виджеты, но новые обои появятся, только когда автоматизация
   сработает снова.

Как настроить каждый вариант, написано в настройках приложения под переключателем.

Карточку для виджетов и обоев выбирает приложение: пока его не открывали, виджет просит
открыть приложение. Когда в выбранных разделах не осталось слов, виджет и обои предлагают
выбрать другие.

## Сборка

Собрать приложение для iPhone можно только на Mac с Xcode. Без Mac это делает GitHub.

На Mac:

```sh
brew install xcodegen
cd ios
xcodegen
open Reci.xcodeproj
```

Проект подписывается командой разработчика, которой принадлежит приложение в App Store
(`DEVELOPMENT_TEAM` в `ios/project.yml`). Чтобы поставить его на свой iPhone из Xcode, нужно
войти в эту команду (Xcode → Settings → Accounts) или выбрать свою в Signing & Capabilities у
целей `Reci` и `ReciWidgets`. Со своей командой идентификаторы `rs.finist.reci`,
`rs.finist.reci.widget` и App Group `group.rs.finist.reci` придётся заменить своими.

## Тесты

| Что | Где запускается | Команда |
|---|---|---|
| Логика: сценарии, файл прогресса, тексты | Linux, через Docker | см. ниже |
| Логика | Mac | `cd ios/ReciCore && swift test` |
| Сборка с виджетами и тесты интерфейса | Mac или GitHub | `.github/workflows/ios.yml` |

Логика на Linux, без Mac и без установки Swift:

```sh
docker run --rm --user "$(id -u):$(id -g)" -e HOME=/tmp \
    -v "$PWD":/src -w /src/ios/ReciCore swift:6.1 swift test
```

Команда запускается из корня репозитория. `--user` запускает Swift от вашего пользователя:
без него файлы сборки в `ios/ReciCore/.build` окажутся принадлежать root.

### На GitHub

Сценарий `.github/workflows/ios.yml` запускается сам при каждом push, который меняет
`ios/`, `tests/` или словарь. Его можно запустить и вручную: Actions → iOS → Run workflow.

1. **Learning logic on Linux:** тесты логики в контейнере со Swift.
2. **App and UI tests on …:** на машине macOS от GitHub ставит XcodeGen, генерирует
   проект, собирает приложение с виджетами и прогоняет тесты интерфейса в симуляторе
   iPhone. На основном телефоне ещё прогоняет тесты логики и собирает `.ipa`. Тесты идут
   параллельно на четырёх телефонах и одном iPad:

   | Машина | Устройство | iOS |
   |---|---|---|
   | macos-15 | iPhone 16 | 18.6 |
   | macos-15 | iPhone SE (3-го поколения), маленький экран | 18.6 |
   | macos-26 | iPhone 17 Pro | самая новая на машине |
   | macos-26 | iPhone 17 Pro Max, 6,9 дюйма | самая новая на машине |
   | macos-15 | iPad Pro 13 дюймов (M4) | 18.6 |

   Образ macos-26 может быть доступен не всем; если его нет, эти строки падают, не мешая
   остальным. Тесты на iPad тоже пока не обязаны проходить. Снимки экранов iPhone 17 Pro Max
   и iPad нужны ещё и App Store: он просит снимки iPhone 6,9 дюйма и iPad 13 дюймов.
3. **Upload to App Store Connect:** после тестов собирает, подписывает и загружает сборку
   в App Store Connect. См. «Выпуск в App Store» ниже.

Результаты тестов интерфейса сохраняются как артефакты `ios-test-results-<телефон>`, по
одному на устройство: `iphone-16`, `iphone-se`, `iphone-17-pro`, `iphone-17-pro-max`,
`ipad-pro-13`. Их можно скачать со страницы запуска и открыть в Xcode.

Снимки главных экранов сохраняются так же, как `ios-screenshots-<телефон>`: PNG-файлы,
названные по экранам, например `ios-screenshots-iphone-se/3-card.png`. Так приложение можно
посмотреть без iPhone и без Mac.

Для открытого репозитория машины GitHub бесплатны. Для закрытого минута macOS считается
за десять минут Linux из бесплатного лимита.

## Как поставить на iPhone без Mac

### Бесплатно, с компьютера на Linux

Сценарий GitHub собирает неподписанный `Reci-unsigned.ipa` для настоящего iPhone. Подписывает
и ставит его ваш бесплатный Apple ID через программу Impactor, которая работает на Linux.

1. После push откройте на GitHub: Actions → iOS → последний запуск → внизу Artifacts →
   `reci-unsigned-ipa`. Скачается zip, внутри `Reci-unsigned.ipa`.
2. Поставьте Impactor: https://github.com/khcrysalis/Impactor. Запасные варианты — Sideloader
   (https://github.com/Dadoum/Sideloader) или AltServer-Linux.
3. Подключите iPhone кабелем, войдите в Impactor своим Apple ID, выберите `.ipa`. Лучше
   завести отдельный Apple ID, не основной.
4. На iPhone, один раз:
   - Settings → Privacy & Security → Developer Mode → включить, телефон перезагрузится;
   - Settings → General → VPN & Device Management → разрешить свой Apple ID.

Ограничения бесплатного аккаунта:

- приложение работает 7 дней, потом его надо поставить заново тем же способом. SideStore
  умеет продлевать приложения на самом телефоне;
- не больше трёх таких приложений одновременно; приложение с виджетами занимает два места
  среди идентификаторов приложений;
- программы установки могут переименовать App Group приложения. Тогда приложение работает,
  а виджеты карточку не видят. Это станет ясно только на телефоне.

### TestFlight

Каждая сборка из `main` попадает в TestFlight (см. ниже): тестировщики ставят её из приложения
TestFlight, без кабеля и Developer Mode, и виджеты точно работают.

## Выпуск в App Store

| Что | Идентификатор |
|---|---|
| Приложение | `rs.finist.reci` |
| Виджеты | `rs.finist.reci.widget` |
| App Group | `group.rs.finist.reci` |

### Сборка и загрузка

Делает GitHub, Mac не нужен. Каждый push в `main`, который меняет `ios/`, `tests/` или словарь,
после тестов запускает задачу **Upload to App Store Connect**:

1. собирает приложение с виджетами на самом новом Xcode (`macos-26`);
2. входит в App Store Connect ключом API; Xcode сам регистрирует идентификаторы и App Group,
   получает облачный сертификат и профили и подписывает сборку;
3. загружает её в App Store Connect. Через 10-30 минут она появляется в TestFlight.

Номер сборки — номер запуска сценария, он растёт с каждым запуском. Версия, например `1.3`,
берётся из `ios/project.yml`.

Ключ лежит в секретах репозитория (Settings → Secrets and variables → Actions):

| Секрет | Что |
|---|---|
| `ASC_KEY_P8` | файл ключа `AuthKey_<id>.p8` целиком |
| `ASC_KEY_ID` | Key ID ключа |
| `ASC_ISSUER_ID` | Issuer ID команды |

```sh
gh secret set ASC_KEY_P8 < AuthKey_XXXXXXXXXX.p8
gh secret set ASC_KEY_ID      # gh спросит значение, и оно не попадёт в историю команд
gh secret set ASC_ISSUER_ID
```

- Без секретов задача ничего не загружает и не падает.
- Сертификаты и профили сам Xcode делает только с ключом роли **Admin**. С ключом роли App
  Manager сборка упадёт на подписи: тогда нужен Admin-ключ или ручная подпись с сертификатом и
  профилями в секретах.
- Ключ даёт доступ к аккаунту разработчика: он хранится только в секретах GitHub, в репозиторий
  не попадает.

### Выпуск версии

1. В App Store Connect: приложение → вкладка iOS-версии → Build → выбрать сборку из TestFlight.
2. Add for Review → Submit. Проверка Apple занимает от нескольких часов до пары дней.
3. После одобрения — Release, если выпуск не автоматический.

После выпуска версия закрыта: новые сборки с тем же номером версии App Store Connect не примет.
Поэтому сразу после выпуска поднимайте `MARKETING_VERSION` в `ios/project.yml` (вместе с
версией Android, `build: Bump version to ...`).
