# Разработка

## Устройство репозитория

| Папка | Что там |
|---|---|
| `app/` | Android-приложение: Kotlin и Compose |
| `web/` | веб-версия: HTML, CSS и JS без сборки |
| `ios/` | приложение для iPhone: SwiftUI и виджеты, см. [ios.md](ios.md) |
| `data/` | исходники словаря и скрипты, которые собирают его для приложения |
| `tests/` | сценарии правил обучения и образец файла прогресса, общие для Android, веба и iPhone |
| `art/` | иконка приложения: `art/izba.py` рисует её для Android и веба |
| `docs/` | описание правил обучения и эта инструкция |

## Сборка Android-приложения

Нужны JDK 17 или новее (подойдёт JBR из Android Studio) и Android SDK.

```sh
cd app
JAVA_HOME=/path/to/jdk ./gradlew assembleRelease
# app/app/build/outputs/apk/release/reci-release.apk
```

Без ключа подписи релизная сборка подписывается локальным отладочным ключом.

Чтобы подписать своим ключом:

1. Держите ключ и файл с его параметрами вне репозитория.
2. Опишите параметры в `keystore.properties`:
   ```properties
   # storeFile указывается относительно этого файла
   storeFile=release.jks
   storePassword=...
   keyAlias=...
   keyPassword=...
   ```
3. Передайте путь к этому файлу при сборке:
   ```sh
   ./gradlew -Preci.signing=/path/keystore.properties assembleRelease
   ```

## Словарь

Словарь собирается из исходников в `data/` в файл `app/app/src/main/assets/words.json`.
Готовый файл лежит в репозитории, так что для сборки приложения пересобирать словарь
не нужно.

- `data/words/*.jsonl`: карточки, по одной в строке. Формат описан в `data/SPEC.md`.
  - `0001-0500.jsonl` … `4001-4500.jsonl`: слова по частотному списку.
  - `extra-words.jsonl`, `phrases.jsonl`, `articles.jsonl`: слова вне частотного
    списка, выражения, разборы похожих слов и заметки.
- `data/accents.tsv`: ударения.
- `data/tips.jsonl`: подсказки «Полезно знать».
- `data/grammar/grammar.json`: справочник.

```sh
python3 -m venv /path/to/venv
/path/to/venv/bin/pip install -r data/requirements.txt
/path/to/venv/bin/python data/scripts/build_json.py
/path/to/venv/bin/python data/scripts/build_grammar.py
```

## Веб-версия

- Код лежит в `web/`.
- Данные берутся из Android-части, а не копируются:
  - словарь и справочник: `app/app/src/main/assets/`;
  - шрифты: `app/app/src/main/res/font/`;
  - номер версии: `app/app/build.gradle.kts`.
- Правила обучения в `web/js/repo.js` повторяют `Repo.kt`. Меняйте их вместе:
  тесты из `tests/learning-scenarios.json` покажут, если реализации разойдутся.
- Публикация: на GitHub Settings → Pages → Deploy from a branch → `main`, `/ (root)`.
  Сайт появится по адресу `https://<логин>.github.io/reci/web/`.
- Проверка у себя:
  ```sh
  python3 -m http.server     # в корне репозитория
  # затем открыть http://localhost:8000/web/
  ```

## Тесты

Общие для Android, веба и iPhone данные лежат в `tests/`, и каждый файл проверяет все три
реализации:

- `learning-scenarios.json`: правила обучения, описанные сценариями. Как устроены сами
  правила, рассказано в [learning.md](learning.md).
- `progress-sample.json`: образец файла прогресса. Все версии должны его загрузить и
  сохранить такой же, иначе файл с одного устройства не откроется на другом.
- `dict-patches.json`: поправки к маленькому словарю и что из них должно получиться.
  Сборка, Android и iPhone применяют их одинаково.
- `telemetry.json`: поля, которые принимает сервер статистики. Сервер отбрасывает пакет
  с любым другим полем, поэтому каждая версия проверяет свои пакеты по этому списку.

| Что проверяется | Команда | Что нужно |
|---|---|---|
| Правила обучения и файл прогресса, Android | `cd app && ./gradlew testDebugUnitTest` | JDK |
| Правила обучения и файл прогресса, веб | `node --test "web/tests/*.test.mjs"` | Node.js |
| Интерфейс веб-версии | `node --test "web/tests/ui/*.test.mjs"` | Node.js и Google Chrome |
| Интерфейс Android | `cd app && ./gradlew connectedDebugAndroidTest` | эмулятор или телефон |
| Логика iPhone | `docker run --rm --user "$(id -u):$(id -g)" -e HOME=/tmp -v "$PWD":/src -w /src/ios/ReciCore swift:6.1 swift test` | Docker |
| Приложение iPhone | GitHub Actions, сценарий `iOS` | Mac или GitHub |

Не проверяются автоматически кнопки, которые открывают системные экраны Android:
разрешения, голос, выбор файла для прогресса.

- Ни один тест не обращается к настоящему серверу статистики:
  - в вебе запросы принимает сам тестовый сервер, по адресу `/srv`;
  - в Android их принимает `FakeServer`;
  - на iPhone приложение, запущенное с `-uitest` или `-uitest-reset`, отвечает на них само.
- Если Chrome называется не `google-chrome`, укажите путь: `CHROME=/path/to/chrome`.
- Тесты интерфейса Android ставят отладочную сборку отдельным пакетом
  `org.kostja.reci.debug`, поэтому установленное приложение и его прогресс не трогают.
- Тест карточки на экране блокировки выключает и включает экран эмулятора. На телефоне с
  PIN-кодом после него экран останется заблокированным.

### Исправления словаря без нового выпуска

Приложения для Android и iPhone раз в день скачивают поправку к встроенному в них словарю.
Поэтому исправленная карточка доходит до телефонов без выпуска новой версии.

1. Исправьте карточки в `data/words/*.jsonl` или справочник в `data/grammar/`.
2. Соберите словарь: `data/scripts/build_json.py` и, если менялся справочник,
   `data/scripts/build_grammar.py`. Они сами пишут и поправки в `dict/`.
3. Закоммитьте вместе словарь и `dict/`, запушьте. GitHub Pages выложит `dict/`, и
   телефоны заберут поправку в течение суток.

Как это устроено:

- **Поправка** — карточки, которые изменились или появились, целиком, удалённые ключи и
  справочник целиком, если он изменился. Она накопительная: от встроенного словаря
  выпуска сразу к текущему.
- **Выпуски** — теги `v*`, в которых уже есть код обновления, за последние полгода, и
  всегда самый свежий. Ставить тег при выпуске как раньше, остальное сборка найдёт сама.
- **Ключи карточек** не меняйте: прогресс привязан к ключу. Удалённая карточка просто
  исчезнет из колоды.
- **Проверка** — сценарий GitHub `Dictionary` падает, если `dict/` не совпадает со
  словарём и тегами: например, если `dict/` не закоммитили или выпуск вышел за полгода.
  Тогда пересоберите поправки сами: `python3 data/scripts/build_patches.py`.
- **В приложении** поправка проверяется по хэшу и формату, хранится рядом с приложением и
  накладывается при каждом запуске. Пока она не скачана целиком, карточки берутся из
  прежнего словаря; сеть никогда не задерживает показ карточки.

### Снимки экранов

`StoreScreenshots.kt` снимает экраны для Google Play и README: карточку, выражение на
экране блокировки, разбор, тёмную тему, справочник, настройки, форму жалобы и раздел
«Обратная связь». В обычном прогоне тестов он пропускается.

1. Запустите эмулятор, например Pixel 6 Pro с Android 17.
2. Снимите экраны:
   ```sh
   cd app && ./gradlew connectedDebugAndroidTest \
     -Pandroid.testInstrumentationRunnerArguments.class=org.kostja.reci.StoreScreenshots \
     -Pandroid.testInstrumentationRunnerArguments.screenshots=true
   ```
3. Заберите их: `adb pull /data/local/tmp/reci-shots` и скопируйте в `screenshots/`.

Тест сам ставит экрану размер 1080×2160 и чистую строку состояния, а после работы
возвращает всё как было.

### Проверки на GitHub

Сценарии GitHub Actions лежат в `.github/workflows/`. Результаты — во вкладке Actions
репозитория; если запуск упал, GitHub пришлёт письмо.

| Сценарий | Когда | Что делает | Что сохраняет |
|---|---|---|---|
| `android.yml` | каждый push | тесты на JVM, отладочный APK; тесты интерфейса на эмуляторах Android 9, 13, 15 и 17 | `reci-debug-apk`, отчёты при ошибке |
| `web.yml` | каждый push | правила обучения и файл прогресса в Node, интерфейс в Chrome | — |
| `dict.yml` | каждый push | тесты сборки поправок; `dict/` совпадает со словарём и выпусками | — |
| `ios.yml` | push, который меняет `ios/`, `tests/` или словарь | логика на Linux; на macOS сборка, `.ipa`, тесты интерфейса в симуляторах трёх iPhone | `reci-unsigned-ipa`, `ios-test-results-N`, снимки экранов `ios-screenshots-N` |

Любой сценарий можно запустить и вручную: Actions → сценарий → Run workflow.

Подписанный релизный APK на GitHub не собирается: ключ подписи остаётся только у
владельца, релиз собирается `build.sh` и выкладывается на страницу Releases вручную.

### Как написать новый сценарий

Сценарий — это шаги и проверки:

```json
{
  "name": "Don't know on a new word brings it back five cards later",
  "settings": {"activeSize": 20, "categories": ["L3"]},
  "steps": [
    {"do": "next"}, {"do": "remember", "as": "a"},
    {"do": "answer", "a": "dontknow"},
    {"do": "until", "word": "a", "max": 30, "answer": "know"},
    {"expect": {"distance": 5}}
  ]
}
```

Настройки сценария (`settings`), все необязательные:

| Настройка | По умолчанию |
|---|---|
| `activeSize`: слов в работе одновременно | 20 |
| `categories`: что учим | `["L3"]` |
| `order`: 0 по частоте, 1 вперемешку, 2 по алфавиту | 0 |
| `reviewKnown`: проверять выученные слова | `true` |

Шаги:

| Шаг | Что делает |
|---|---|
| `next`, `prev` | «Дальше» и «‹» |
| `answer` | ответ на текущую карточку: `know`, `dontknow`, `long`, у статей `hide` и `later` |
| `remember` | запомнить текущую карточку под именем |
| `skim` | пролистать `count` карточек, отвечая `answer` на слова и `articles` на статьи |
| `until` | листать, пока не вернётся запомненная карточка; её расстояние попадёт в `distance` |
| `untilArticle` | листать до первой статьи |
| `advanceDays` | перемотать время вперёд |
| `set` | поменять `activeSize` посреди сценария, как в настройках |
| `showAgain` | показать ту же карточку ещё раз: экран блокировки и приложение, перезагрузка страницы |
| `restart` | перезапустить приложение: память о текущей сессии теряется, сохранённое остаётся |
| `fav`, `showArticlesAgain` | избранное и «Снова показывать» из настроек |
| `pick` | запомнить первое слово уровня по частоте или по алфавиту |

Проверки (`expect`): фаза, серия, состояние, срок проверки и число показов запомненного слова, текущая
карточка, расстояние, номер карточки, размер активного набора, число скрытых статей, что
было на каких карточках пролистанного отрезка и сколько на нём разных слов. Полный список — в обоих исполнителях:
`app/app/src/test/java/org/kostja/reci/LearningScenariosTest.kt` и
`web/tests/learning.test.mjs`.
